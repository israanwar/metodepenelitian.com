# AI Safety Academic Integrity

## Purpose
This document defines the platform's position on how AI may participate in a researcher's work: as an advisor and co-pilot that suggests, critiques, summarizes, and points out gaps, never as a ghostwriter that produces submittable academic text on a researcher's behalf without disclosed AI involvement. This is a foundational safety and integrity boundary for an academic platform, not a preference — it governs prompt design, feature framing, and export behavior across the whole AI surface.

## Scope
Covers the advisor-not-ghostwriter principle, what AI-assisted output the platform will and will not produce, disclosure requirements when AI has materially contributed to text a researcher exports or submits, and how this principle is enforced across engines. Does not cover the technical hallucination/citation-accuracy mechanisms — see [AI HALLUCINATION CONTROL.md](AI%20HALLUCINATION%20CONTROL.md) and [AI CITATION GROUNDING.md](AI%20CITATION%20GROUNDING.md). Does not cover institutional plagiarism-detection tooling, which is a distinct integrity-tooling integration tracked under [MASTER AI GOVERNANCE.md](../MASTER%20AI%20GOVERNANCE.md), not authored here.

## Responsibilities
- Frame every AI-assisted engine's output as a suggestion, draft input, or critique for the researcher to evaluate and rewrite in their own words, never as finished prose presented as ready to submit under the researcher's name unmodified.
- Require the advisor-not-ghostwriter clause (defined here, versioned via [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md)) in every prompt template for an engine whose output could plausibly end up in a submittable academic document — Methodology Advisor, Evidence Synthesis Engine, Research Gap Engine, and any future drafting-assistance surface.
- Attach a disclosure marker to any exported or copied text block that was substantially AI-generated, so the researcher's own downstream record-keeping (and any institutional disclosure requirement) has the information available, without the platform deciding on the researcher's behalf what counts as a disclosure-worthy contribution in every institution's specific policy.
- Refuse specific request patterns that cross from "help me think about this" into "write my thesis/paper for me" — e.g. a request for full-length submittable prose with no analytical framing — by redirecting the model toward structured suggestions, outlines, or critique instead.
- Keep this boundary consistent across every model/provider used, including under Core Contract #11 fallback conditions — a degraded provider must not be used as a loophole to produce ghostwritten text a primary provider would have declined to frame as such.

## Non-Responsibilities
- Does not implement plagiarism or AI-text detection on researcher-submitted content — a separate integrity-tooling integration, not owned here.
- Does not enforce any specific institution's academic-integrity policy (citation style requirements, disclosure thresholds) — those vary by institution and are the researcher's own responsibility to follow; this document sets the platform's own behavioral floor, not a substitute for institutional policy.
- Does not verify factual accuracy of AI output — see [AI HALLUCINATION CONTROL.md](AI%20HALLUCINATION%20CONTROL.md) for that distinct concern.
- Does not decide what a researcher does with AI-assisted drafts after export — the platform's responsibility ends at disclosure-marker attachment and advisor-framed output; it cannot control downstream use.
- Does not gate account-level access based on suspected misuse patterns — that would be a separate trust-and-safety mechanism, not defined in this document.

## Core Components
- **Advisor-Not-Ghostwriter Clause** — the mandatory prompt instruction, composed into every academic-facing prompt template via [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md), directing the model to produce structured suggestions, critiques, and drafts-for-revision rather than finished submittable prose.
- **Ghostwriting Request Pattern Guard** — a check applied to inbound requests (and reinforced in the prompt itself) that redirects requests explicitly asking for full submittable text with no analytical scaffolding toward an advisor-shaped response instead.
- **AI-Contribution Disclosure Marker** — metadata attached to any exported text block substantially generated by AI, informational for the researcher's own record-keeping, not a platform-enforced watermark.
- **Engine Framing Review** — a design-level check applied when any new engine is built, confirming its default output shape is advisory (outline, critique, suggestion set, annotated draft) rather than a finished document.

## Owned Data
- `AIContributionRecord` — per exported or copied text block: which engine/request produced the AI-generated portion, extent (fully AI-drafted paragraph vs. AI-suggested edit vs. AI critique only), timestamp, linked to the disclosure marker shown to the researcher.

## Inputs
- Researcher requests across every AI-assisted engine, screened against the Ghostwriting Request Pattern Guard.
- Export/copy actions from any AI-assisted surface, triggering disclosure-marker attachment.
- The advisor-not-ghostwriter clause content, versioned centrally in [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md).

## Outputs
- Advisor-framed AI responses (suggestions, critiques, structured drafts requiring researcher rewriting) across every engine.
- `AIContributionRecord` entries attached to exported content, surfaced to the researcher as a visible disclosure note.
- Redirected responses when a ghostwriting-pattern request is detected, explaining the platform's advisor-only stance rather than silently complying or silently refusing without explanation.

## Dependencies
- [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md) — carries the versioned Advisor-Not-Ghostwriter Clause into every academic-facing template.
- [AI HALLUCINATION CONTROL.md](AI%20HALLUCINATION%20CONTROL.md) — a related but distinct safety layer; both apply to the same AI outputs for different reasons (accuracy versus authorship integrity).
- [architecture/04 RESEARCH AI ORCHESTRATOR.md](../architecture/04%20RESEARCH%20AI%20ORCHESTRATOR.md) — the orchestration layer where the Ghostwriting Request Pattern Guard is applied before dispatch.
- [architecture/11 EVIDENCE SYNTHESIS ENGINE.md](../architecture/11%20EVIDENCE%20SYNTHESIS%20ENGINE.md) — a primary engine whose default output framing (synthesis notes, not a finished literature-review chapter) is a direct application of this principle.
- [MASTER AI GOVERNANCE.md](../MASTER%20AI%20GOVERNANCE.md) — the governing policy this document specifies for the academic-integrity dimension.

## Extension Points
- A new drafting-assistance engine adopts the Advisor-Not-Ghostwriter Clause by composing it from [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md)'s shared clause library rather than defining its own framing from scratch.
- A future institutional-policy integration (letting an institution set stricter disclosure thresholds than the platform default) can extend `AIContributionRecord` without changing its core shape.
- The Ghostwriting Request Pattern Guard's detection rules can be refined over time (from simple pattern matching to a more nuanced classifier) without changing what happens once a request is flagged — redirect toward advisor framing.

## Security & Privacy
- `AIContributionRecord` entries are scoped to the researcher's own `ResearchProject` and are private by default, per Core Contract #9 — the disclosure marker is for the researcher's own use, not a record shared with the platform's other users or made externally visible without the researcher's own export action.
- The platform does not report suspected ghostwriting-pattern requests to any institution or third party — the guard redirects the researcher's own session, it is not a surveillance or reporting mechanism.
- Disclosure-marker metadata is retained under the same data-lifecycle rules as the rest of the project's content, governed by [MASTER DATA GOVERNANCE.md](../MASTER%20DATA%20GOVERNANCE.md).

## Failure Modes
- **Guard circumvention via incremental requests** — a researcher assembles a full ghostwritten document through many small, individually reasonable-looking requests rather than one obvious ghostwriting request; this is a known, hard limit of a per-request guard and is mitigated only partially by consistent advisor-shaped framing at every step, not fully solved by this document's mechanisms alone.
- **Over-refusal harming legitimate use** — the guard misclassifies a legitimate request (e.g. asking for a properly-scaffolded draft paragraph as a starting point) as a ghostwriting attempt, frustrating genuine advisory use; mitigated by keeping the guard's default response a redirect toward advisor framing, not an outright refusal, preserving usefulness.
- **Disclosure marker lost on copy outside the platform** — once a researcher copies AI-assisted text into an external document, the platform cannot enforce that the marker's information travels with it; this is an acknowledged boundary of the platform's responsibility, not a solvable technical gap.

## Observability
- Rate of requests redirected by the Ghostwriting Request Pattern Guard, per engine, to monitor whether framing needs adjustment.
- Volume of `AIContributionRecord` entries generated per export action, as a usage-pattern signal.
- Any user feedback specifically about the advisor framing (too restrictive / not clear enough), routed to prompt-review per [AI PROMPT REGISTRY.md](AI%20PROMPT%20REGISTRY.md).

## P0/P1/P2/P3
**P0.** This principle is foundational to the platform's legitimacy as an academic tool; an AI feature that produces submittable ghostwritten text without disclosure would undermine the platform's core value proposition and expose researchers to integrity violations, so this boundary must be enforced before any drafting-capable engine ships.

## Current Status
Documented, not implemented. No Ghostwriting Request Pattern Guard, `AIContributionRecord` schema, or disclosure-marker UI exists yet. This document defines the required behavioral floor for engines to be built against.

## Open Questions
- Exact granularity of the "extent" field on `AIContributionRecord` (binary AI-generated/not vs. a finer scale) — not yet decided.
- Whether the disclosure marker should be a passive metadata note or an active, visible watermark in exported documents — a product decision not yet made.
- How the Ghostwriting Request Pattern Guard should be tuned per engine (Methodology Advisor's "suggest a design" is inherently more generative than Evidence Synthesis's "summarize these sources," and thresholds may need to differ).
- Whether institutional partners will eventually be able to configure a stricter-than-default integrity posture for their affiliated researchers — not yet evaluated.
