Keputusan Terbuka

Empat hal yang perlu diputuskan sebelum P0 mulai dikerjakan — bukan detail implementasi, tapi keputusan arsitektur yang mahal diubah kalau salah di awal.

01

Statistical Execution Layer (#46) butuh sandboxing eksplisit — menjalankan kode statistik pengguna (R/Python) di proses yang sama dengan API utama adalah risiko keamanan. Perlu diputuskan: worker terisolasi, container per-run, atau layanan pihak ketiga.

02

SINTA dan GARUDA (#27, #28) — kamu sendiri menandai "jika akses dan terms memungkinkan". Ini bukan keputusan teknis, ini keputusan legal/lisensi yang harus selesai sebelum Integration Gateway mengalokasikan slot untuk keduanya, supaya tidak membangun connector untuk sumber yang ternyata tidak boleh diakses programatik.

03

Vector Database (#106) ditandai P1, tapi Semantic Search (#17) dan Research Gap Engine (#35) yang P1 sama-sama bergantung padanya. Perlu satu keputusan awal: vector DB terpisah (Pinecone/Weaviate/Qdrant) atau ekstensi di database relasional (pgvector) — pilihan ini mempengaruhi biaya infrastruktur P1 secara keseluruhan, bukan cuma satu fitur.

04

AI Provider Layer (#9) harus diputuskan strategi fallback-nya sebelum Orchestrator dibangun: kalau provider utama gagal/rate-limited, apakah otomatis pindah provider lain, atau gagal eksplisit ke pengguna? Ini menentukan bentuk interface adapter-nya dari awal, mahal diubah setelah orchestrator jadi.
